# 長時間運転（オフライン、AC-24 の補い）

測定日: 2026-10-03。**実機なし（デバイスは開いていない）のオフライン試験**。AC-24「8 時間連続で使う → XRUN の増加 0、メモリの増加 50 MB 未満、クラッシュ 0」のうち、**XRUN は実機のデバイスでしか測れないので、ここでは測っていない**。AC-24 そのもの（実機で 8 時間）は**まだ**で、依頼者の実機確認として残る。

- テスト: `Source/Tests/SoakTests.cpp`
  - `KoeLoom.exe --run-tests Diag` の「Soak (offline AC-24)」: 音声 `KOELOOM_SOAK_HOURS` 時間ぶん（既定 8）。途中経過は exe の隣の `soak-progress.txt`
  - 既定の実行（Integration）の「Soak (short)」: 同じ内容を音声 3 分で。見つけた不具合 2 件の回帰テストもここ
- 機械: Intel Core i7-11700F、Windows 11。Release ビルド（ブランチ `wave3/soak`）

## 何を流したか

AppController をデバイスなし（`AppController (false)`）で立ち上げ、アプリと同じ部品をそのまま使う: VoiceProcessor → EffectChain → Soundboard → モニター（`IMonitorSink` → `MonitorOutput`。デバイス側は 44.1 kHz のヘッドホンのつもりでテストが `pullForTest` で引く）。48 kHz・480 サンプルのブロックをできるだけ速く回した。

- 入力: 合成音声 `synthVoice` のループ。10 分ごとに 2 分の完全な無音、36 秒の DC オフセット（+0.25）、24 秒の大音量（4 倍。前半は ±1 で切れた波形、後半は 1 を超えたまま）、37 秒ごとに 50 ms のほぼフルスケールのノイズ
- 操作（乱数の種は固定。8 時間で約 2 万 8 千回）: 内蔵プリセット 61 本を 30 秒ごとに順に（960 回、各 15〜16 周）、変換 ON/OFF、ミュート、スロット ON/OFF（ホットキー経由も）、エフェクトの追加・削除・移動、つまみのランプ（30 fps で書き込み）、ピッチのランプ、重ねる声（追加・削除・ON/OFF・固定 / スケール連動）、サウンドボード（ループ・単発・重ねがけ・すべて停止・音量。44.1 / 22.05 kHz の WAV を読み込み時に変換）、フリーズ / ルーパー、入力ゲイン・ゲート・ノイズ抑制・出力ゲイン（+12 dB まで）・ダッキング・モニター音量、お気に入りの前後
- デバイスの開き直しのまね（`AppController::reprepareForTests`、`openDevicesIfReady()` と同じ手順）: 44.1 kHz / 441、44.1 kHz / 1024、48 kHz / 960 に移って 14 分 24 秒後に 48 kHz / 480 へ戻す、を 3 回（計 6 回）
- 30 fps のタイマーの仕事（`collectGarbage`、メーター、トーストの回収）はテストが 3 ブロックごとにやり、Windows のメッセージも回してコントローラーとサウンドボードのタイマーを動かした

## 調べたこと

毎ブロック: 出力に NaN/Inf が無い、ピークがリミッターの天井（-1 dBFS）以下、L = R、`process()` とモニターの引き出しの間にメモリ確保 0（AC-39 と同じ確保検知）、`process()` の中で FTZ/DAZ が立っている、モニターの出力が有限で天井以下。
ほかに: プリセットを読んだ直後（音声区間）に無音になっていない、同じプリセットの遅延の表示が毎回同じ、サウンドボードの再生位置が音の長さの中、1 時間ごとのブロックの処理量（スレッドの CPU サイクル。ほかのアプリの負荷に左右されない）が後になって増えていない、長い無音のほうが声より重くない（非正規化数の見張り）、プライベートメモリの増加（10 分の慣らしの後 → 終わり）が 50 MB 未満、終わった後に変換 ON・ミュートなしで声が出る。

音声 8.00 時間（2,787,609 ブロック）を実時間 696 秒（41 倍速）で処理。テストの実行全体（Diag の他の項目を含む）は 745 秒。

- **処理量の傾き: なし**。8 時間目の平均は 1 時間目の 0.90 倍、p99 は 0.96 倍。時間ごとの差（±10 % ほど）はその時間に入っていたエフェクトと重ねる声の違い
- **メモリ: 慣らし後 44.3 MB → 終わり 47.3 MB（+3.0 MB）**。途中は 31.7〜49.1 MB を上下（サウンドボードの読み直しとチェーンの作り直しのたびに動く）で、増え続ける傾きはない。ワーキングセットは 56.8 → 60.1 MB
- 出力のピーク -1.00 dBFS（天井ちょうど）、NaN/Inf 0、L ≠ R 0
- モニター: ピーク -1.0 dBFS、天井超え 0、アンダーラン 0 / オーバーラン 0
- 音声スレッドでのメモリ確保 0、`process()` の中で FTZ/DAZ が立っていた
- 長い無音の平均 493 kcyc、声 612 kcyc（無音のほうが軽い。非正規化数による遅くなりは見えない）
- 遅延の表示（アルゴリズム分のみ。デバイス分は入らない）: 33.0〜85.0 ms、プリセット × ノイズ抑制の 122 通りで、同じ組み合わせの値は毎回同じ
- プリセットを読んだ直後の無音 0、サウンドボードの位置の異常 0、ループ音が途切れずに続いた最長 34.1 分（「すべて停止」と 8 音の上限で切れるまで）
- 終わった後: 「そのまま」-13.2 dBFS、「ヘリウム」-12.6 dBFS（RMS）。止まっていない
- クラッシュ 0

## 見つけて直した不具合

1. **モニターの出力が天井を超える（1 回目の 8 時間で検出）**。410 サンプルが天井を超え、ピークは +0.9 dBFS（モニター音量 0 dB のとき）。VoiceProcessor はモニターのミックスを -1 dBFS で切るが、`MonitorOutput` の適応リサンプラー（Catmull-Rom）が、切れて角ばった波形で最大 1.25 倍まで行き過ぎる（A, A, -A, -A の中間で 1.25 A）。補間の後で天井に切るようにした（`Source/Engine/MonitorOutput.cpp`、1 行）。回帰テストは修正なしだと 1.114 で落ちる。3 分の短い版では出なかった
2. **デバイスをより大きいバッファで開き直すと、古いチェーンがヒープを壊す（試験を組む途中で、コードを読んで発見）**。開き直しでは `AudioEngine::open()` がプロセッサを新しいブロック長で準備してデバイスを動かし、新しいチェーンはその後で作られる。それまでと 30 ms のクロスフェードの間、古いチェーン（たとえば 480 で準備）に大きいブロック（960 や 1024）が渡り、480 サンプルの `dry` バッファへはみ出して書いていた。最初にデバイスを開くときも、デバイスのバッファが 480 より大きければ同じことが起きる。`EffectChain::process` が準備したブロック長より長いブロックを分けて処理するようにした（`Source/Engine/EffectChain.cpp/.h`）。回帰テストはエフェクトに渡ったブロックの最大長が 480 以下であることを見る。8 時間の試験には 44.1 kHz / 1024 と 48 kHz / 960 への開き直しを入れてある

## この試験でわからないこと

- **XRUN**（実機のデバイスとそのタイミングが要る）。AC-24 の XRUN の条件は実機で確かめるしかない
- 音声スレッドとメッセージスレッドの並行性: ここでは 1 本のスレッドが両方を交互にやるので、スレッドの間の競合は試していない
- 実機のドライバー、WASAPI の開き直しそのもの、モニターの 2 台のデバイスの時計のずれ（`04-monitor-drift.md` で別に試した）
- 実際の声。入力は合成音声
