# T3 RNNoise の組み込み（(c)）

**入力は合成音声で代用**（`phase0/testdata/reference-speech.wav` が無いため。`synthVoice` 10 秒、seed 7、ピーク -6 dBFS）。基準音声を置けば `p0_rnnoise` で同じ測定をやり直せる。生の値は `03-rnnoise.csv`、条件は `03-rnnoise-run.txt`。

## 測定条件

- 48 kHz、モノラル、float32。1 フレーム 480 サンプル。Release ビルド。オフライン（デバイスを開かない）。
- JUCE のブロック長が 480 の倍数でないとき用の**リングバッファの橋渡し**（`RnnoiseBridge`）を実装した。入力をためて 480 たまるごとに 1 フレーム処理し、出力 FIFO から取り出す。出力 FIFO は最初に `480 − gcd(ブロック長, 480)` 個のゼロで埋める。k 回目のブロックまでに処理済みのフレームが足りない量は `(k·B) mod 480` で、その最大が `480 − gcd(B, 480)` なので、これが「一度も足りなくならない最小の固定遅延」になる。
- 遅延の実測は、入力と出力の波形の相互相関（1 秒目から 2 秒間、0〜2400 サンプルを探索）と、1 ms 刻みの RMS 包絡の相互相関の両方。
- 「-40 dBFS のホワイトノイズ」は **RMS で -40 dBFS** の一様乱数（振幅 0.01·√3）と定義した。

## 結果: 遅延

| ブロック長（サンプル） | FIFO の初期遅延（サンプル） | 実測の遅延（波形、サンプル） | 実測（ms） | 相関 | 包絡での実測（ms） | FIFO の枯渇 |
|---|---|---|---|---|---|---|
| 480 | 0 | 960 | 20.000 | 0.9756 | 20 | 0 |
| 128 | 448 | 1408 | 29.333 | 0.9756 | 29 | 0 |
| 256 | 448 | 1408 | 29.333 | 0.9756 | 29 | 0 |
| 512 | 448 | 1408 | 29.333 | 0.9756 | 29 | 0 |

- **RNNoise 自体の遅延は 960 サンプル = 20.000 ms**（仕様 §5.4 の「約 10 ms」と違う）。内訳はソースで確認した: 分析窓 960 / 間隔 480 の重ね合わせ（`frame_analysis`、`frame_synthesis`）で 480、さらに v0.2 は**1 フレーム先を見てから前のフレームに利得をかける**（`rnnoise_process_frame` が `st->delayed_X` に利得をかけて合成し、そのあと今のフレームを `delayed_X` に移す）ので、もう 480。
- ブロック長が 480 の倍数でないと、FIFO の分（128 / 256 / 512 では 448 サンプル = 9.333 ms）が足される。240 なら 240、160 なら 320 になる（式から）。**ノイズ抑制を使う構成では、バッファ 480 が遅延の最小**。
- 合成音声だけ（ノイズなし）を通したときの音量の変化: **-0.401 dB**（1 秒目以降、遅延を補正）。

## 結果: 抑制量

| 入力 | 測った区間 | 入力 (dBFS) | 出力 (dBFS) | 抑制量 (dB) |
|---|---|---|---|---|
| ホワイトノイズ単独（RMS -40 dBFS、10 秒） | 1〜10 秒 | -39.998 | -96.972 | **56.973**（AC-16 の「10 dB 以上」に**合格**） |
| 合成音声 + ノイズ: 音声の 0.3 秒の切れ目（ノイズだけ） | 1 秒目以降の切れ目、前後 50 ms を除く | -39.999 | -85.405 | **45.406** |
| 合成音声 + ノイズ: 音声のある区間 | 同上 | -21.816 | -22.366 | 変化 -0.550 |
| 合成音声だけ（同じ切れ目つき） | 同上 | - | - | 変化 -0.353 |

- ノイズ単独の出力は、最初の 1 秒が -65.738 dBFS、2 秒目以降は -91.094〜-106.431 dBFS（1 秒ごとの値は CSV）。立ち上がりの 1 秒は抑制が弱い。
- 音声 + ノイズの入力の SN 比は 18.114 dB（音声のある区間の RMS と、ノイズの RMS の差）。音声は 0.7 秒鳴らして 0.3 秒止める形にした（10 ms でフェード）。基準音声（§5.1）は 0.5 秒を超える無音を含まないので、同じ切れ目を人工的に入れて測る。
- RNNoise は実際の話し声で学習されている。合成音声を「声」と見なす度合いは実際の声と違うはずなので、抑制量と音声の目減りは**基準音声で測り直す**必要がある。

## 結果: 処理時間

条件: 合成音声 + RMS -40 dBFS のノイズを 60 秒（10 秒を 6 周）、各ブロック長で 6000 フレーム。計測スレッドは MMCSS「Pro Audio」。**依頼者のゲームと Discord が動いている状態**（PC 全体のビジー率は表の列）。

| ブロック長 | 1 フレームの処理時間 p50 / p99 / 最大 (µs) | コールバックあたり（ブリッジ込み）p50 / p99 / 最大（バッファ時間に対する %） | PC 全体のビジー率 |
|---|---|---|---|
| 128 | 155.600 / 325.400 / 1408.400 | 0.038 / 8.104 / 52.942 | 62.1 % |
| 256 | 154.700 / 326.500 / 1532.200 | 2.790 / 4.766 / 28.817 | 61.8 % |
| 480 | 155.600 / 344.300 / 2337.900 | 1.608 / 3.542 / 23.465 | 65.1 % |

- 1 フレーム（10 ms ぶん）の処理は p50 で 155 µs 前後 = 10 ms の約 1.6 %。バッファ 128 ではフレームを処理するコールバックとしないコールバックが混ざるので、p50 は小さく p99 が大きい（フレームを処理するコールバックは 2.667 ms に 155 µs 以上 = 5.8 % 以上）。
- 通常の優先度で測った最初の値（ゲーム実行中、ビジー率 92.0〜99.8 %、10 秒）は、バッファ 480 で 1 フレーム p50 231.300 / p99 2118.800 / 最大 5763.000 µs だった。p99 と最大は優先度で大きく変わる。
